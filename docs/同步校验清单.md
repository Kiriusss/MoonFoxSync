# 心狐同步的同步校验清单

一次备份可能在三处读取同一份内容。采集时客户端读需要重新计算摘要的本机原件（08），上传时读 NAS 所缺的本机缓存对象（19），NAS 发布前再从自己的对象库验证候选版本（24、25）。**上传显示 100% 时，NAS 可能还在读磁盘**。如果刚好触发历史保留策略，还可能需要验证受影响的其他版本（40）。

Mac 上，连续监听且确认干净的项目可以跳过本轮采集（02）。已经排队的上传仍按电源、来源和网络策略单独判断。下面把触发条件、读取位置和调整代价分别列出，便于按编号讨论。

## 本机决定是否采集

| 编号 | 触发与当前检查 | 实际读取 | 调整的影响 |
|---|---|---|---|
| 01 | 桌面调度先看总开关和电源。电池默认仅手动，也可选择每 1 或 4 小时检查；接电后立即尝试运行。代理再按来源的手动、仅家庭、跟随网络策略与最小间隔判断。 | 系统电源状态、偏好、上次预约或下次到期时间、SQLite | 电池策略限制自动采集和自动上传。用户仍可主动检查或从待传输页上传；「立即检查」继续遵守来源策略和间隔。 |
| 02 | Mac 对本地来源比较实际根路径、目录身份、文件系统事件代次、已确认的绑定代次、基线和忽略选择。连续监听有效且最近 24 小时核对通过才能跳过。新进程、监听丢事件或根目录被替换后重新核对。 | 根目录元数据和配置；命中时不遍历该项目，不读正文 | 这是项目级快路径。Windows 按电源和来源间隔调度，到期后进入文件遍历；普通文件与 Codex 的缓存行为分别见 07、14。 |
| 03 | 同项目的扫描预约、设备清理锁、项目活动锁、Codex 专用锁和缓存收集锁决定能否开始。取消的扫描只释放自己的预约。 | 小锁文件和 SQLite | 防止重入、删除中的项目被继续采集、别的任务尚未登记的对象被清走。 |
| 04 | 绑定时排除与客户端数据目录重叠的位置。采集时核对绑定、来源类型、登记的目录身份和凭据文件边界。已执行「删除本机文件」并标记暂停的来源不会自动采集或上传。 | 路径、文件系统属性、数据库 | 防止换盘或来源被替换后读错项目。通过原位置按需功能释放的个别文件仍可随项目采集，见 06、10。 |
| 05 | Git 来源核对工作区标记。全备份模式包含新出现的 Git 忽略文件，仍排除用户取消选择的项目成员；选定模式由 Git 枚举成员，再加手选的忽略文件。采集跳过 .git 和嵌套仓库。 | Git 工作区查询、目录项、选择表 | 决定备份范围。普通非 Git 目录同样按文件夹采集。 |
| 06 | 真正扫描时枚举并排序目录项，检查类型、文件身份、大小、权限和时间，读取符号链接目标。归档链接另核对登记设备、原路径、父目录身份和链接目标。 | 目录项及元数据，不读取链接指向的 NAS 文件 | 确认新增、删除、改名、执行位和链接变更；几十万文件时元数据遍历也有成本。 |
| 07 | 普通文件复用摘要时比较卷、文件 ID、状态变更时间 ctime、修改时间 mtime 和大小。索引按目录载入，刚变化的文件及跨卷成员保守重读。 | 本地 APFS、ext 系列、Btrfs、XFS、tmpfs 的适用卷上，命中只读元数据。Windows 普通文件在每个实际采集轮次读取正文。 | 仅凭大小和 mtime 会漏掉等长改写后恢复时间戳的文件。Windows 的 Codex 历史另有句柄签名缓存。 |
| 08 | 新文件、变动文件或索引缺失时，按 4 MiB 切块，计算块 SHA-256、整文件 SHA-256 和清单地址。小于一块的非空文件直接复用块摘要，多块文件从同一次源文件读取计算两种摘要。 | 本机文件全文；多块文件有两种计算 | 块摘要用于去重与传输，整文件摘要用于恢复、下载和跨端核对。旧版首次升级需要给已有本机文件建索引。 |
| 09 | 打开文件后和读完后比较身份和属性；采集结束再复核目录和成员元数据，确认根目录仍是同一目录。Unix 对每个目录的成员元数据算摘要，Windows 使用对应的逐项检查。 | 第二遍目录元数据；普通文件正文不因此再读一遍 | 防止编辑器、构建程序或另一个进程在扫描中换掉文件，造成混合版本。此项会随项目文件数量增长。 |
| 10 | 创建本机对象时检查已有缓存对象的类型和长度。新版本要复用未重读的文件时，检查文件清单及所引用缓存块的类型和长度；碰到缺失对象可从未变源文件重建并比对摘要。按需文件在真正形成新版本时核对清单中的长度和整文件摘要。 | 清单、缓存块元数据；缺失修复才读普通源文件正文 | 避免有版本记录却缺少上传所需的数据。无变化轮次跳过整理完整对象引用。 |
| 11 | 根摘要等于旧版、或等于已记录的恢复后本机基线时，无名采集复用旧版。普通来源自动检查还会比较有差异的子树，按名字、类型、内容摘要、可执行位和链接目标判断。时间戳及项目里普通文件 .DS_Store 的单独变化不创建时间点。 | 有差异的目录清单；文件内容按已有摘要比较 | 单独绑定的 .DS_Store 仍是用户文件。历史基线缺失时保留候选版本；显式命名快照仍能保存。 |
| 12 | 形成时间点前，事务内再次比较绑定路径、绑定代次、基线、忽略选择，再同时写版本与引用。 | SQLite | 避免用户在扫描中重绑项目、改变选项时保存到错误基线。 |

## Codex 来源的专用检查

| 编号 | 触发与当前检查 | 实际读取 | 调整的影响 |
|---|---|---|---|

## 传输与 NAS 发布

| 编号 | 触发与当前检查 | 实际读取 | 调整的影响 |
|---|---|---|---|
| 16 | 家庭上传核对私网 IPv4、物理网卡、直连路由、本地地址和配对服务器公钥指纹。家庭传输的每次 HTTP 请求重新检查出接口和本地地址，TLS 建连时验证证书。 | 路由、网络接口、证书；无项目正文 | 逐请求查路由有启动外部命令的开销。可改为监听网络变化并在变化后失效；失效处理必须能识别 Wi-Fi 与 Tailscale 切换。 |
| 17 | 外出小任务估算新增对象及协议开销，检查大文件清单头、单次上限和滚动 24 小时余额；传输中按实际字节计费。 | SQL、长度、清单头；不为估算重哈希正文 | 维持设置中的外出流量限制。可缓存同一未变任务的估算。 |
| 18 | 上传前核对项目和快照、父版本是否已发布、是否已有回执及另一传输是否占用；NAS 验证设备、角色、资料库、请求 ID、草稿字段与会话有效期。同一请求重试复用会话或回执。 | 两端数据库、请求字段、设备凭据 | 防止重复发布、父版本未就绪和传错资料库。 |
| 19 | 客户端先报价相对已发布父版新增的对象。NAS 在同一资料库和本会话内判断可复用性；客户端只发送服务端列为缺少的对象，并在发送前核对缓存对象 SHA-256。 | 协商读索引；发送时读本机缓存里的清单或数据块 | 上传端验存盘后取出的对象。若省略这次哈希，损坏数据可到达网络，接收端仍会在 21 拒收。 |
| 20 | 上传进度从目录和文件清单计算总文件数、总字节与各文件分配。已有子树总量会被复用。 | 本机清单元数据和 SQLite；不为进度读取块正文 | 影响进度和剩余量显示，首次统计大树有成本。 |
| 21 | NAS 对上传的原始对象或批量对象核对会话、已登记的对象、类型、长度、请求限制及实际收到的 SHA-256。 | NAS 收到的字节 | 保证进入对象库的字节与对象名匹配。 |
| 22 | NAS 落盘遇到同名对象或并发抢先安装时，重开已有对象核对长度和 SHA-256；正常新对象采取临时写入、同步、原子安装并保存目录项。 | 已存在分支读 NAS 对象正文；新写入的 fsync 是持久化操作 | 避免损坏文件被当成成功去重。fsync 影响延迟，与重复算哈希是两类开销。 |
| 23 | NAS 在读取对象前检查是否可从本会话已收对象或本资料库可见版本引用。父版存在且提交返回 OBJECTS_MISSING 时，客户端在同一会话重报价全部对象一次，只补传 NAS 要求的内容并重试提交。 | 授权预取及缺项查询读数据库；遍历验证见 24、25，补传见 19 | 在父版可见历史被清理后恢复传输，也防止引用另一个资料库的私有对象。 |
| 24 | NAS 从根验证目录及文件清单，检查名称、类型、编码、排序、分页结构、摘要地址、嵌套深度和逻辑条目总数。一次目录树验证内，相同目录或文件清单摘要只展开一次；同一子树挂载多次仍计入逻辑总数。 | NAS 目录与文件清单 | 整棵候选树都会参与判定，跨版本没有沿用上次验证结果。可评估复用已验证的不可变子树。 |
| 25 | NAS 针对每种不同的文件清单核对块长度与 SHA-256。单块文件直接拿已验证的块摘要与整文件摘要比较；多块文件按清单顺序送入整文件哈希器，复用读块时已取得的字节；空文件校验空内容摘要。附件逐个另行验证。 | **NAS 候选版本引用的正文，包括此前已上传的内容。** 不同文件共享某块，或同一文件重复引用该块，都可能多次从磁盘读取该块。 | 发布阶段是调查「100% 后等待」的首要位置之一。预取授权和去重文件清单不会免除存量块验证。改为只深查新对象，需要另定存量对象的复查时机。 |
| 26 | NAS 在事务内复查设备与写权限、回执、父版本和历史删除状态，按期望主线及共享项目证明判定推进还是分叉，写对象引用并执行保留策略。客户端检查回执的版本、资料库、根摘要和发布结果。 | 通常为两端数据库；共享基线证明见 32，保留策略命中时的额外正文读取见 40 | 防止并发覆盖和重复提交。管理员已验证的冗余头可按 39 找到保留主线；普通手动删除不会授予这种重定向。 |

实现见 [网络与流量策略](../client/engine/policy.go)、[上传与回执](../client/engine/sync.go)、[进度计算](../client/engine/upload_progress.go)、[NAS 接收及提交](../server/upload.go)、[对象与文件验证](../internal/objectfmt/format.go)和[目录树验证](../internal/objectfmt/tree.go)。

## 下载、恢复与按需读取

| 编号 | 触发与当前检查 | 实际读取 | 调整的影响 |
|---|---|---|---|
| 27 | NAS 列目录时沿路径读目录清单，并读当前页各普通文件的清单以取大小和摘要。文件 GET 另查资料库授权、可见版本与成员，核对 If-Match 和 Range。每个与范围重叠的块都整块读入核验，随后输出指定字节。 | 列目录和受管文件 HEAD 只读清单；GET 读实际覆盖的完整块 | 小范围请求也可能读一个 4 MiB 块。固定版本和强 ETag 防止把不同版本的片段拼到一起。 |
| 28 | 常规受管下载、列目录及 ZIP 导出中的对象通常经过 Store.read 和格式解析器 get，两层都对同一批内存字节求对象 SHA-256。按对象 ID 直接取原始对象时只走 Store.read。 | 受管清单或块读入一次后可能计算两次对象 SHA-256。完整受管 GET 按块核验，直接使用文件清单中的整文件摘要作 ETag。 | 可以统一这些入口的对象校验责任。发布已经使用单层对象加载；历史重建仍有两层，见 40。 |
| 29 | 恢复到本机新目录时，先逐页核对成员名、路径、深度及链接是否越界。每个文件单独下载，要求 200、匹配的强 ETag 和内容长度，写临时文件的同时计算整文件 SHA-256、核对实际字节数并同步落盘。所有文件完成后再发布恢复目录。 | 客户端读取各文件的完整响应一次；常规目录恢复不重新打开所有临时文件求摘要 | 可发现短传、串版本和损坏。并行度按文件计算；单文件内部的哈希保持流式。缓存下载和原位置取回见 41，接收 NAS 版本并切换项目目录见 43。 |
| 30 | 原位置 WebDAV 核对本地挂载入口、槽位、设备、归档阶段及固定版本记录。HEAD 直接使用本机归档的长度和 ETag。GET 向 NAS 发送 If-Match；范围请求再核对 206、Content-Range 和长度。 | 完整非空响应在本机边转发边求整文件 SHA-256，匹配才交付最后一字节；部分响应计字节并依赖 NAS 的分块验证。 | 保留记录在建立归档时确认。每次 WebDAV 读取不会另发请求核查该保留记录；若版本已不可读，NAS 的 GET 会失败。 |
| 31 | 外部只读文件的 GET、HEAD 和 Range 都先把原件复制到临时文件并求摘要，再打开原路径复核身份、属性与全文摘要，通过后才按条件返回。受管项目的 ZIP 从指定快照串流生成，验证对象并限制并发、处理不安全的归档名。 | 外部原件读两遍且写一份临时副本，即使是 HEAD 或很短的 Range。受管 ZIP 读取归档中的文件，并按条目生成 ZIP 校验码。 | 外部文件可被其他程序原地修改。要降低这条路径的磁盘开销，可讨论可信快照或带失效条件的缓存。 |

实现见 [NAS 文件读取](../server/reads.go)、[桌面恢复](../client/engine/restore.go)、[按需读取](../client/engine/workspace_dav.go)、[外部目录读取](../server/external.go)和 [ZIP 导出](../server/archive.go)。

## 只在特定操作运行的检查

| 编号 | 触发与当前检查 | 实际读取 | 调整的影响 |
|---|---|---|---|
| 32 | 导入或手动统一项目时，检查来源身份、重叠目录、远端项目与所选基线；需要基线证明时，按所选成员计算忽略时间戳的内容指纹。 | 本机可能读项目正文；NAS 对既有快照主要读树与清单 | 防止两台电脑同名但内容不同的工作区被当成同一条可覆盖主线。 |
| 33 | 项目状态查询读取 NAS 库状态与 Git 缓存。macOS 的周期界面刷新要求接入电源且主窗口或状态栏面板可见；静默启动等待用户打开界面再刷新。Git 缓存过期后的轻量检查会查工作区、分支、上游与远端引用，不下载缺少的提交。显式深查及「同步远端 Git」另核对分叉、工作区状态和快进条件。 | NAS 与 Git 元数据、工作区状态及按需远端请求。轻量远端检查的缓存窗口为 15 分钟。 | 项目状态与时间点采集有各自触发条件。原有未提交修改可在界面持续显示，直至提交或撤销。 |
| 34 | 合并核对分支、主线、共同祖先、预览依据及冲突选择。预览文本按需读有限前缀；提交手工编辑的文本会重新分块求摘要。合并结果沿目录和文件清单收集实际引用。 | 清单和冲突预览内容；合并提交沿用已发布文件的块引用，无需重读所有未改正文 | 防止旧预览覆盖新主线，并保留合并结果可独立读取所需的引用。 |
| 35 | 原位置释放预览按大小、时间、执行位及 Git 跟踪情况筛选。macOS 实际释放或删除普通本机文件时校验已发布版本、文件身份、正文、占用状态和适用的扩展数据；原文件移到暂存名后，在替换或 unlink 前再验。 | 常规本机文件可能完整读取两次；已经归档的占位链接检查槽位和链接目标 | 两次检查覆盖移动前后的竞争窗口。删除本机文件还写恢复意图并暂停该来源，避免随后把本机清空同步到 NAS。 |
