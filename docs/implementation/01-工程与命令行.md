# 工程与命令行

## 1. 工具链和进程

Go 1.27.x、单 module，初始 module path 为 `kirius.local/kiriusdrive`，用 `go.mod` / `go.sum` 固定依赖。核心使用 `net/http`、`crypto/tls`、`crypto/sha256`、`database/sql`；SQLite 首选 `modernc.org/sqlite`，首个工程任务锁定实测通过的依赖补丁版本。NAS 目标为本机核实过的 fnOS / Linux amd64，Mac 基线为 Apple Silicon，Windows 为 x64。客户端与服务端使用独立数据库。桌面端只有一个设备后台能写本地任务与额度账本。

| 目标位置（开发时创建） | 责任 | 主要依赖与测试替身 |
| --- | --- | --- |
| `cmd/kdrive-server`、`server/` | 启动 TLS 服务、本机管理命令、设备授权、变更发布、对象生命周期 | SQLite 与同卷对象目录；可注入故障磁盘、时钟、提交后丢响应 |
| `cmd/kdrive-agent`、`client/engine/` | 持久化任务、扫描和采集、网络判断、下载、恢复、驻留状态、本机 IPC | 可注入物理路由、TLS 探测、文件事件、时间与远端返回 |
| `cmd/kdrive` | 用户 CLI，调用本机后台，提供人类可读输出或 JSON | 本机 IPC；具有同一语义的桌面菜单复用后台操作 |
| `internal/objectfmt/` | 纯函数编码、解码、排序、摘要、块范围计算 | 无文件系统、数据库和网络依赖；固定摘要向量在存储规格 |
| `internal/protocol/` | v1 请求响应、错误映射、快照绑定、可取消传输 | 契约以 [OpenAPI](openapi.yaml) 为准；测试启动本地 TLS 端点并注入断流 |
| `client/macos/`、`client/windows/` | Swift 6 / SwiftUI + File Provider；C# / .NET 10 LTS / WPF + WinRT / CFAPI | 平台层翻译枚举、取回、取消、移除等事件，后台负责判定许可 |
| `client/android/`、`client/harmony/` | Kotlin / Compose 和 ArkTS / ArkUI 独立应用 | 仅依赖 HTTPS 只读接口和系统查看器 |
| `testdata/`、`tests/integration/` | 协议样本、可重建目录、故障与真实性能记录 | 测试临时目录，不依赖个人 GitHub 工作区或线上数据库 |

构建工单以 `go test ./...`、原生支持平台上的 `go test -race ./...` 和三个目标的核心产物为入口。NAS 核心构建例为 `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o dist/kdrive-server ./cmd/kdrive-server`。Xcode/Windows SDK/Android SDK/DevEco Studio 分别完成原生组件的签名、安装与真机运行。M0 交付实际编译器版本、最低实测系统、架构和安装方式。跨编译成功和真机运行分别记录。

## 2. CLI 契约

这些命令是待实现的用户入口。路径由本机文件选择器或参数提供，时间和 ID 由后台返回。CLI 支持 `--json`；错误和诊断写到 stderr，stdout 只含所选结果，自动化脚本用结构化错误码分支。秘密从系统凭据库、交互输入或受保护文件读取。服务端管理命令经本机受限管理通道执行。

| 命令形式 | 语义与结果 |
| --- | --- |
| `kdrive-server serve --config <file>` | 验证数据卷、数据库版本、TLS 证书后监听配置地址。启动失败返回非零并给出原因 |
| `kdrive-server unit add --name <name> --kind managed` | 建立可授予其他设备的托管资料库，返回单元 ID。既有目录使用 `--kind external --root <path>`，需在 NAS 上执行 |
| `kdrive-server pair issue --role reader --unit <id>` | 生成一次性配对信息，凭据仅能获得列明的权限。同步设备使用 sync 角色；允许自动建立散文件单元时另授予创建单元能力。已配对设备可用管理命令 `kdrive-server unit grant <unit> --device <id> --role <reader或sync>` 增加授权；设备撤销入口为 `kdrive-server device revoke <id>` |
| `kdrive pair --server <https-url>` | 交互核对管理员提供的服务指纹与一次性凭据；成功后将设备秘密交给 OS 凭据库 |
| `kdrive unit bind <id> --path <file-or-dir> --profile <profile> --preview` | 输出范围、规则、排除、嵌套、预估初传与 Git 覆盖；移除 `--preview` 后登记已审阅的范围。相同目录不能归属两个重叠写入单元 |
| `kdrive snapshot <unit> --name <label>` | 捕获工作区，返回本地快照 ID、父版本、采集结果；断网也可生成。远端状态单独显示 |
| `kdrive sync <unit> --snapshot <id> --now` | 仅放行这个明确版本，返回传输估计和任务 ID；自动任务与之后的新版本仍走网络策略 |
| `kdrive queue`、`kdrive pause <job>`、`kdrive resume <job>` | 返回网络分类、等待原因、方向、总量／剩余量；暂停和恢复持久化，重启可继续 |
| `kdrive history <unit>`、`kdrive diff <unit> <a> <b>` | 查看主线和分叉，摘要相同的命名快照仍能单独查看。可选路径用于查看单文件历史差异 |
| `kdrive restore <unit> <snapshot> --to <new-dir>` | 下载并校验到新目录，支持 `--path <relative>` 恢复一个成员。重试不能覆盖目标新修改；写入受管工作区后只有另行发布才产生 NAS 新版本 |
| `kdrive pin <unit> --path <relative>`、`kdrive release <unit> --path <relative> --preview` | 固定离线或预览本机回收，根路径可省略。正式释放先取得版本保留凭证，再复核并安全回收。普通目录通过 `kdrive archive` 执行并在设备目录中保留取回入口 |

任务类 JSON 的最小公共字段为 `jobId, unitId, snapshotId, direction, state, reason, remainingBytes`。估算未知用 JSON null。退出码约定为 0 成功或已持久排队，2 参数错误，3 需配对或重新授权，4 网络或服务不可用且请求未受理，5 本地状态冲突或前置条件不满足，1 其他失败。NAS 回执丢失时后台对账，CLI 显示“待确认”；仅凭已发送字节数不可显示“NAS 已保存”。

`kdrive archive` 和 `release` 的 UI 默认展示受影响成员及已持久保存的确切版本。历史分叉处理统一提供“还原到新目录”和“发布整理结果”两个动作。后者由 `kdrive resolve <unit> --fork <id> --from <dir>` 采集整理好的内容，以最新主线为父，附上被处理的分叉 ID；若主线再次变化，服务端仍返回可找回的分叉。

## 3. 服务端配置样例

该 JSON 展示直接在 NAS 宿主机启动时的配置字段。首次初始化单独以本机管理命令 `kdrive-server init --config <file>` 建库，校验卷挂载源，生成 store-id 并记录挂载身份；重复执行只报告已初始化状态。配置和私钥由服务账号读取。启动应显式报出不可绑定的接口、证书不匹配和错误的数据卷，便于选择实际可用的监听方式。

```json
{
  "formatVersion": 1,
  "dataDir": "/vol2/kiriusdrive",
  "listen": ["192.168.1.10:7443", "100.64.0.10:7443"],
  "tls": {
    "certFile": "/etc/kiriusdrive/server.crt",
    "keyFile": "/etc/kiriusdrive/server.key"
  }
}
```

7443 是可调整的试运行端口。若 Tailscale 在独立网络命名空间或网关运行，应将其私网入口转发到实际监听地址，同时保留端到端 TLS 验证。单机开发可以将 listen 配成回环地址并使用专门的测试 CA。初始化**必须明确选择数据目录**；正式服务启动只打开已经登记的库。服务进程不接受通过远程 API 更改本机文件系统根目录。

## 4. 证书、地址和可诊断性

为同一个 NAS 配置一个服务身份及家庭、Tailscale 两个拨号地址。示例家庭地址为 `192.168.1.10`、tailnet 地址为 `100.64.0.10`。两端可以使用带相应 SAN 的服务证书；也可以拨指定 IP 并保持正确的证书主机名。信任的 CA 或指纹由本机管理员配对时交付。证书轮换须通过原信任关系或重新配对。同名 Wi-Fi、低延迟、Tailscale direct 或能打开端口均不能单独激活家庭策略。

服务与后台分别记录请求 ID、任务 ID、单元 ID、版本 ID、传输字节、耗时与决策原因，以便追踪“为什么此任务仍在外出队列”。普通日志不记配对码、Bearer 令牌和文件正文。验收时另行保存 OS、存储类型、家庭或外出路径、冷／热缓存、重试次数和测试数据摘要。真机事实与模拟测试结果分别标记。
