# 心狐同步 v1 开发入口

**已决策：NAS 服务端、桌面后台和 CLI 采用 Go。** Mac 使用 Swift，Windows 使用 C#，Android 阅读端使用 Kotlin，原生鸿蒙阅读端使用 ArkTS。本文档包定义 v1 的实现基线。开发版已提供可运行的同步服务、桌面核心和阅读端，已实现的能力与使用方法见[快速开始](../../快速开始.md)。

一名后端开发者可以从 [HTTP 契约](openapi.yaml) 和 [存储与版本](02-存储与版本.md) 实现 NAS。桌面开发者从 [工程与命令行](01-工程与命令行.md) 和 [桌面与调度](03-桌面与调度.md) 开始。Android、鸿蒙开发者从 [移动只读](04-移动只读.md) 和同一份 HTTP 契约开始。任务依赖、固定数据集与通过条件在 [交付与验收](05-交付与验收.md)。

| 涉及实现的决定 | v1 约定 |
| --- | --- |
| 文件、配套文件、项目的区别 | 一次操作作用于一个单元的一份明确版本。一个代码项目是一棵树，NAS 上只向其他设备发布完整快照 |
| 传输与驻留 | 网络传缺失对象。电脑分别记录“固定离线／已下载／仅 NAS”；清理本机需要 NAS 保留引用及本机版本复核 |
| 何时传 | 物理家庭路由与同一服务身份均通过验证才能使用家庭连接。默认外出仅手动，可开启 10 MiB 单项、10 MiB 整批、滚动 24 小时 100 MiB 自动预算 |
| 历史与并发 | 快照有父版本，命名检查点与工作树共用历史模型；过时基线生成可找回的分叉。恢复到新目录和发布恢复版本是两个动作 |
| 谁可写 | 配对后的桌面同步设备按资料库授权。手机只读。已有 NAS 目录需要显式登记，手机可读当前内容；历史查看适用于托管快照 |
| 如何核对实现 | 请求字段、状态码和媒体类型以 OpenAPI 为准；摘要字节格式以存储规格为准；策略决定以桌面规格为准。修改任一协议必须一起更新对应样例和跨端验收 |

**首个联调切片。** 一个本机 NAS 测试进程、一个上传客户端、一个只有读权限的客户端。上传目录中含一份小文本和一个空目录；读端在发布前只见旧版本，发布后能列目录、分段读取文本。模拟发布成功后丢失响应，上传端重试仍得到同一回执。先让这条流程通过，再接入五万文件项目、系统占位和移动界面。

[首轮联调固定请求与应答](fixtures/first-sync.json)提供同一棵树的四个对象、可直接解码的测试正文，以及上传未完成、幂等回执、目录分页入口、只读设备和字节范围读取的预期结果。可替换设备及服务端分配的 ID 重放。
