# Android 与原生鸿蒙阅读端

## 1. 交付物与界面

原生 Android 应用使用 Kotlin + Jetpack Compose，鸿蒙 NEXT 应用使用 ArkTS + ArkUI。两个安装包共享 [HTTP 契约](openapi.yaml)、错误语义、测试账号和验收数据。各自使用系统网络、凭据库与文件预览能力。首版交付以下页面。

| 页面 | 进入条件与动作 | 必须显示的状态 |
| --- | --- | --- |
| 添加 NAS | 从管理员取得服务 URL、证书信任信息和只读配对码；名称仅用于显示 | 私网未连、证书不符、配对过期、已撤销分别提示；重试保留已输入的非秘密字段 |
| 资料库 | 登录成功后列举获准资料库 | 托管项目可看快照；已有 NAS 目录展示“当前文件”。权限回收后重新枚举 |
| 目录和历史 | 先取指定快照元数据，再按路径和游标取一页目录。初始每页 100 项，滚动追加；返回上一级保留位置 | 显示版本时间、分叉标识、名称、类型和大小。跨页固定快照；切换快照时丢弃旧游标。缓存目录可展示“上次更新” |
| 文件 | 用户点开才请求正文，复制位置或保存到本机通过系统交互完成 | 显示准确版本、大小、已取字节、预计下载量、取消与重试；预览失败仍可选择下载 |
| 缓存和设备 | 清除应用缓存、查看占用、移除本机配对 | 仅清理本应用在该账号下的缓存及授权。用户已通过系统导出的文件归用户管理 |

## 2. 客户端读流程

1. **配对。** 在系统安全存储生成并保存设备秘密；按契约向已验证的 NAS 发送配对请求。Android 采用 Android Keystore 保护应用秘密，鸿蒙采用平台密钥存储保护本地凭据。NAS 端每次按设备和资料库授权。设备时间或隧道异常时保留诊断原因，不能以关闭 TLS 校验恢复连接。
2. **浏览。** 通过 `GET /v1/units` 取得授权单元。托管单元先选 `snapshotId`，再调用 `/units/{unitId}/entries`（API 基址为 `/v1`）。相对路径按查询参数编码且只编码一次；根目录传空路径。既有 NAS 目录使用 external 单元，不传快照 ID。列表页的请求数随打开的页数增长，列目录不触发正文读取。
3. **阅读。** 对所选单元、版本及路径调用 `/content`。托管文件绑定固定快照，如果 NAS 在阅读中发布新版本，当前阅读继续取原版本。支持单段字节范围请求；完整下载验证响应长度以及契约提供的摘要。文本文档先取至多 256 KiB，再逐页获取。解码器保留跨块的 UTF-8 尾字节，二进制或无法识别编码时提供下载。图片使用缩放解码；PDF 使用支持随机访问的查看器，或完整缓存后交给系统阅读器。媒体仅对原生解码器支持的格式启用拖动读取。
4. **续读。** 首段响应记录强 ETag。续传发送 `Range` 和 `If-Match`；只有 `206`、起止位置、总长度、ETag 与期待完全匹配才拼接。若收到 `200` 则重新从零写新临时文件；`412` 说明源版本已变，提示重新打开；`416` 检查总长，清理过期任务并重取状态。网络断开或取消时关闭响应并记录已核实区间。应用重启先验证授权和版本再恢复。[HTTP 条件与范围请求](https://www.rfc-editor.org/rfc/rfc9110)
5. **普通 NAS 目录。** NAS 运维端登记选定的只读根路径。客户端只见单元和相对路径。外部根没有托管快照历史；服务器为读到的内容提供稳定的表示与强校验值。中间文件变化必须能安全重启，禁止拼接前后两个版本。确保可用空间与耗时能在目标 NAS 上承受，M1 必测大型可变外部文件。
6. **移动网络。** 手机默认仅加载元数据。用户在蜂窝或未知网络打开预计需要完整下载且超过 10 MiB 的文件时，先显示大小，允许继续或取消。文本分段阅读、媒体分段读取按用户请求执行。系统预览要求完整文件时明确告知下载量。手机的读操作不会放行桌面的待传大任务，也不改变其他设备的固定和释放状态。

## 3. 缓存、格式与平台边界

缓存键至少含服务身份、设备账号、单元 ID、托管快照 ID 或外部文件 ETag、相对路径。索引记录逻辑长度、校验值、完整区间、最近访问和临时状态。仅已完整校验的文件能导出到外部阅读器。读取缓存与正在写入的部分文件分开，完成后原子替换。v1 建议缓存上限 512 MiB，按最近使用清理临时副本；超过缓存上限的单个文件允许用户显式选择导出至系统目的地。离线只展示已缓存目录和已取内容，标记离线时间。设备收到撤权时终止新请求、删除受管凭据与该账号缓存；已导出副本无法远程回收。

- **Android。** 前台阅读随页面生命周期取消无用请求；下载到应用沙箱，交给外部应用时使用 FileProvider 临时只读 URI。用户主动“另存”走系统文件选择器。Tailscale Android 负责私网通路。[Android 安全共享](https://developer.android.com/training/secure-file-sharing) · [Android Tailscale](https://tailscale.com/docs/install/android)
- **鸿蒙。** 网络请求、范围与取消使用对应 API 级别的 Network Kit；在应用沙箱完成下载，通过系统预览能力判断是否有合适阅读器。部署记录保留 DevEco、SDK、机型和系统版本。社区 VPN 客户端只作为候选通路：须从 KiriusDrive 原生应用在蜂窝网络下读通目标 NAS，并核验 TLS 身份；若使用随身网关则将该条件写入验收结果。[Network Kit](https://developer.huawei.com/consumer/cn/doc/HarmonyOS-Guides/http-request/) · [华为文件预览](https://developer.huawei.com/consumer/cn/doc/HarmonyOS-guides/preview-filepreview/) · [MeshArc 项目](https://github.com/flypigJ/Tailscale-OHOS)

**可用性判定。** 连接失败区分“无私网路由”“证书不匹配”“设备已失效”“文件在此版本不存在”“预览格式不支持”。认证和权限状态以服务端响应为准；超时可重试同一只读操作。只读凭据不能借已知摘要、缓存游标或其他资料库的路径读取未获授权内容。

## 4. 两个客户端各自必须跑通的场景

| 编号 | 输入与动作 | 可观察结果 |
| --- | --- | --- |
| R1 | 蜂窝网络，经私网配对并打开指定旧快照的源码 | 读到旧版摘要；记录实际机型、路由、证书身份和 NAS 请求 ID |
| R2 | 浏览 5 万文件项目的根目录和第 2 页，跳回上一级 | 请求只含元数据；对照 NAS 日志，文件正文传输为 0 字节 |
| R3 | 下载 12 MiB 文件，收到前 4 MiB 后断开；外部源换成同长度新内容再恢复 | 托管文件可续读原快照，外部文件按版本变化提示重开。最终文件只有一个版本的内容 |
| R4 | 一台手机只获准资料库 A；尝试列 B、读 B 的文件、建上传会话；之后撤销设备 | NAS 不返回 B 的内容，拒绝写入；撤销后后续网络访问失败。另一台读设备仍可使用自身权限 |
| R5 | 打开图片、PDF、无预览器的二进制；取消下载，清空缓存 | 图片、PDF 按支持能力阅读；其他格式可显式保存。取消能中止请求，清缓存后 NAS 文件和版本保持可读 |
