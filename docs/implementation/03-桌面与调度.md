# 桌面端实现规格

Mac 和 Windows 对同一版本、同一事件序列必须做出相同的调度决策。`kdrive-agent` 拥有索引、任务和额度账本的写入权。CLI、菜单栏、托盘、Finder、资源管理器的请求在同一后台汇合。网络字段和服务器返回值以 [OpenAPI](openapi.yaml) 为准；内容摘要与树结构见[存储与版本](02-存储与版本.md)。

## 1. 接入范围和分类

一个 managed unit 有独立的历史、当前版本和访问授权，对应一次原子发布。一个项目选一个单元；同一个目录中需要分别排队、发布和恢复的散文件，以独立单元登记。一个文件组可以用同目录的多个精确成员或一条配对规则登记。文件、组、项目和实验批次共享上传、历史、恢复协议。用户可按规则一次预览并批量登记整目录，无须逐文件点选。创建新单元需服务端赋予创建权限；缺权限的项显示“等待绑定”，可改绑已授权的单元。创建权限对应 OpenAPI 的 `canCreateUnits`。多设备共享同一历史须显式选择同一 NAS unit ID。同名路径不自动合并，其他设备的单元列表仅返回其已有读取权限的单元。批量接入使用本机持久映射和幂等请求，重试只补未登记的项。

| 本地 profile | 选取成员 | 触发条件 | 历史与取回 |
| --- | --- | --- | --- |
| `file` | 指定的一个文件 | 保存稳定 | 一个文件一个版本 |
| `group` | 指定成员，或同目录、同文件名主干的 RAW 与 XMP；区分必须/可选成员 | 必须成员就绪，所有变动稳定 | 完整组清单。显式查阅其中某个文件允许只读该成员 |
| `project` | 已登记目录，Git 与非 Git 项目均支持 | 静默采集或手动命名 | 项目一条队列记录，整树发布和历史比较 |
| `batch` | 指定实验输出目录及所需日志、数据、索引等成员 | 手动“结束本批”，或生产工具约定的完成标志 | 完成前只显示采集进度；成员再次写入会使就绪判定失效 |
| `package` | 系统识别或用户指定的文稿包目录 | 整包稳定 | 一个逻辑文档；同包成员共享快照 |

首先校验根路径身份与访问权限，再分配嵌套单元，然后执行显式纳入/排除、Git 规则、类型推断。项目内的图片和权重保留项目归属，扩展名只决定阅读方式或传输开销。两个单元重叠时，仅允许显式排除或拆分后登记。拆出数据集时父项目历史可独立推进；选择“代码与数据须配套”时，对外展示的组合版本固定引用两个具体完整版本，并在所有引用可用后切换。接入活跃数据库或虚拟机时要求上游提供一致性导出；数据库的 WAL 文件不能作为可忽略的普通临时文件处理。

### 本机规则样例

以下 JSON 为 `kdrive-agent` 本地配置格式示例。示例单元 ID 由 NAS 签发，`rootPath` 仅保存在本机。默认外出模式 `manual`，用户选择 `small` 才启用小任务自动传输。策略解析使用整数个字节。

```json
{
  "version": 1,
  "network": {
    "awayMode": "small",
    "memberLimitBytes": 10485760,
    "jobLimitBytes": 10485760,
    "rolling24hBytes": 104857600
  },
  "bindings": [{
    "unitId": "01J8Q2SJNN8XB42T0QS6JJ6ZHG",
    "rootPath": "/example/FlightSim",
    "profile": "project",
    "gitIgnoreUntracked": true,
    "gitRefs": ["refs/heads/main", "refs/tags/v1.0"],
    "exclude": ["out/cache/**"],
    "separateRoots": ["runs"],
    "quietSeconds": 5,
    "rescanAfterSeconds": 60
  }]
}
```

`rescanAfterSeconds` 为持续变动时距离上次排入采集的最大等待时间。`separateRoots` 使用根内相对路径，标记边界；运行结果的独立根另行绑定。路径规则使用斜线，区分大小写，`*` 限当前层、`**` 可跨层；绝对路径、空组件、`..`、重复归属和未知键均报告错误。预览显示已跟踪但被显式规则排除的文件、嵌套边界及机器相关元数据。更改规则生成下一版范围修订；新修订只对新快照生效。原历史仍可按旧清单恢复。根目录被卸载、改指其他卷、扫描无权限或返回 I/O 错误时暂停采集，不能根据空扫描生成批量删除。

独立数据集在父规则修订中记作范围边界。选择“配套发布”时，父快照的 `links` 为 `{mountPath,unitId,snapshotId}` 列表，工作树中对应挂载位置不再重复保存子树；先持久化两个版本，再发布固定链接的上层快照。接收方分别检查对子单元的授权。Git bundle 在快照 `attachments` 中引用经校验的文件清单，不创建或占用用户工作区路径。

## 2. 本机索引与归档区

数据目录位于每用户应用状态目录，须在同步根之外。数据库启用外键、WAL 和关键事务持久化。每个数据库使用单实例锁；后台重启先对账，再接受新文件事件。令牌保存在 Keychain / Windows 凭据库，SQLite 仅保存凭据引用。以下是数据库最低字段和唯一性；字段名为本地约定，`id` 使用 ULID，摘要用 SHA-256，字节用 64 位非负整数。

| 表（主键） | 必需字段 | 写入时机与约束 |
| --- | --- | --- |
| `binding(unit_id)`、`rule_revision(unit_id, revision)` | 根路径、平台文件身份、卷 ID、profile、规则正文、active_revision、同步根类型、服务器游标与已见 head | 登记、改规则、重新对账时事务写入；物理根无重复写入归属 |
| `entry(unit_id,path)` | 文件身份或空、类型、扫描代次、大小、时间戳、exec、内容摘要、所属本机基线版本、dirty 代次 | 路径按规范存储，不按宿主系统折叠大小写。mtime 只作重扫提示；替换同名文件重新校验身份和摘要 |
| `capture(snapshot_id)`、`capture_object(snapshot_id,kind,digest)`、`spool(kind,digest)` | 父 ID、根摘要、规则版本、标签、捕获状态、暂存对象大小和位置 | 完整对象先同卷写临时文件并持久化、原子重命名，再提交索引。不完整的采集不能被调度。活跃捕获、待确认上传和恢复日志的引用阻止回收 |
| `job(job_id)`、`object_progress(job_id,kind,digest)` | 单元、版本、方向、操作、所选相对范围、优先级、state/reason、会话 ID、幂等键、重试时刻、人工暂停、已确认对象 | 活跃任务按单元/快照/方向/范围/操作去重。以同一幂等键重试相同请求，记录服务端对象回执；本机“已发出”不算远端持久化 |
| `receipt(unit_id,snapshot_id)`、`presence(unit_id,path)` | 发布结果、根摘要、回执、驻留意愿、已安装摘要、最新目录版本、归档引用 | 本机驻留与发布状态独立。显式路径规则优先于最近的祖先规则；默认按需。更新目录版本不会清空“仅 NAS”意愿 |
| `fs_operation(op_id)`、`fs_step(op_id,path)` | 恢复/回收类型、快照、原文件身份和摘要、暂存位置、目标意愿、远端保留记录、阶段、错误 | 改动文件系统前先写意图，逐路径记录完成。崩溃后根据磁盘和 NAS 实况重做或报告差异；操作 ID 在重试时保持不变 |
| `traffic_lease(lease_id)`、`traffic_event(event_id)` | job、通道代次、预留量、已用量、结算状态；应用层字节、时间、上下行、manual/auto | 多任务共用一账本，使用短事务预留、结算和记账。对 event 时间、job 状态及重试时刻、capture_object.digest 建索引 |

每个任务的 `direction` 区分上传和下载。收敛到同一目标版本的前台/后台请求可合并底层读，调用方保留独立的等待与取消状态。命名检查点和离线版本有稳定的身份，不能通过合并队列悄悄改指新文件。磁盘不足时保留已持久的检查点与用户源文件；待采集与已安全保存须在 UI 分开显示。

## 3. 生成可重放的项目历史

1. **发现变化。** 登记根先全量扫描；Mac FSEvents 或 Windows 目录变更通知只记脏路径和代次。监听溢出、更换卷、系统恢复或上次退出时监听游标不可信，触发重扫。常规保存静默 5 秒开始，连续 60 秒至少排入一次尝试。手动命名立即尝试。
2. **确定 Git 覆盖范围。** 用 Git 只读查询取得仓库根、HEAD、工作树、索引跟踪路径与忽略规则；用支持 NUL 分隔输出的命令处理带换行或空格的文件名。读取磁盘工作树的当前内容，记录已跟踪文件被移除的变动；已跟踪文件即便现在命中 `.gitignore` 也继续纳入。未跟踪文件默认服从忽略规则。`.git` 目录或指针文件均不进入普通扫描。执行 Git 子进程使用参数数组、可取消调用、可选锁关闭、禁用递归外取；Git 不可用或仓库处于难以判读的状态时明确显示覆盖缺口。
3. **固定输入。** 对变化条目用同一打开句柄读取并记录读前后身份、大小、时间和事件代次；按存储规格生成不可变块及清单。读取期间重新命名、替换或触发写事件的条目重排，最终复核目录成员与扫描代次。获取内容时按类型保存符号链接本身，不跟随链接到项目外。若源系统持续任意并发改写，多文件读取无法保证同一瞬间的应用一致性；此时使用生产应用给出的快照或完成标志。
4. **离线封存。** 同卷 spool 保存重传所需的不可变数据，与索引确认后才显示“已存本机”。确有长期保留引用的 NAS 祖先对象可复用；若本机唯一剩下的是可被整理掉的旧回执，必须先补齐本机 spool 或验证新的留存引用，才能将该版标为可重放。某对象只在上一待传快照的 spool 中时，两份快照都保留引用。后来源文件再次修改也不能改变已封存内容。快照链按父版本依赖次序上传。未知父版本先补祖先；有意的并发分支保留原父版本与分叉回执，不能把本机旧基线换成服务器最新 head 来强行发布。
5. **Git 历史附加件。** 仅归档用户选中的 refs 及可达对象，记录每个 ref 的精确对象 ID。导出前后复核 refs，变动则重试；新目录验证 bundle、恢复 refs 后叠加工作区快照。分离 HEAD 的记录只说明来源，单靠工作区不能恢复原暂存内容。Git 子模块还需各子仓库的 refs/工作区；linked worktree 的公用 Git 目录由其自身仓库管理；LFS 指针与实体分别登记。缺 Git 对象的浅克隆、未到本机的 LFS、未纳入的 stash、reflog、hooks、索引状态和配置，均在覆盖列表标注。这些内容的缺口不得通过整目录原地移除而丢失。[Git ignore](https://git-scm.com/docs/gitignore) · [Git bundle](https://git-scm.com/docs/git-bundle)

新远端版本到达时，持久化目录与变化游标须同一事务提交。仅 NAS 的成员只更新目录；已固定或已驻留的更新进入策略队列。构造新快照时，`presence=nas_only` 的成员从同步基线的持久清单补入，普通目录内文件缺席和原生占位均不触发删除或隐式回填。已归档路径同名重建须与该目录基线比较；服务端也变动时进入并发版本。在客户端中明确删除仅 NAS 条目才产生删除意图。本机存在修改时先保留本机工作区并捕获其原基线，提供“查看两个版本”“另存到新目录”。向已有工作区还原前逐条比较基线；冲突文件保留并结束为待处理。下载到新目录本身不会推进服务器 head，在工作区完成恢复后创建并发布一份新快照才会更新历史。

## 4. 调度和网络边界

任务正常路径为 `capturing → local_saved → queued → negotiating → transferring → awaiting_receipt → published`。同祖先并发发布可结束为 `fork_saved`；下载对应 `queued → transferring → verifying → applying → installed`。人工暂停、断网、等待家庭路径、等祖先、额度耗尽分别写作 `paused`/`waiting` + 原因码及恢复条件。NAS 校验错误重读本地不可变对象；根身份变化或摘要再次不符须提示修复。网络重试采用带随机扰动的指数退避，1 秒起步、上限 5 分钟；出现网络或人工恢复事件时允许提前重判。请求作用域与版本须复核，重启不沿用旧 socket。

**家庭链路。** 将登记的 LAN 拨号地址和服务端 TLS 身份绑定。Mac 查询到该地址实际选路的物理接口和下一跳，Windows 查询路由和网卡；只接受登记的物理 LAN 路径，拒绝 VPN/隧道接口和未经登记的路由网关。Wi-Fi 名称可用于触发探测。握手在候选物理路径进行，校验证书信任链及主机名或已登记的服务指纹，建立独立传输连接；固定拨号地址与 TLS 主机名可以不同。家庭传输禁用代理、重定向和外网自动回退。网络事件或路由变化提高 `routeEpoch`、取消旧通道，下一块开始前核验代次；在途写可产生部分流量，不能承诺切网瞬间的零字节。TLS 身份不符拒绝该端点；只能用独立验证通过的 tailnet 端点按外出规则继续。

**一次调度循环。**

1. 检查单元权限、暂停、源一致性与父依赖。无网络只排队。显式“立即”绑定 `unit/version/direction/scope`；静默后台、Finder 预览、杀毒索引和系统打开回调均不得伪造人工令牌。受限网络上用户需要显式从菜单或应用授予一次大文件取回。
2. 经验证的家庭连接放行受管任务。外出 manual 模式保持队列静止，仅主动打开目录或用户授权的任务产生相应请求。small 模式先检查内容有变化的成员最大完整逻辑长度（阈值 10 MiB，含等于）。删除或纯改名按清单计费用；未变化且可复用的 6 GiB 权重不参与单成员限制。仅改一个字节但内容已变化的 6 GiB 权重仍受限。
3. 分页协商缺失对象。单任务门槛计此次自动协商与版本所需清单、请求/响应正文及待传缺失内容，阈值 10 MiB；超限前停止协商或推迟整个任务。实际线上编码开销也需计入预算（包括 JSON/Base64 包装时的膨胀）。同任务跨重启或多次协商的账目需保留。任务下载读取绑定目标快照；禁止因块很小就把逻辑大文件计成小文件。
4. 每设备、所有单元和自动任务上下行共用滚动 24 小时 100 MiB。字节口径是 HTTP 请求/响应正文长度，包括清单、应用重试、预览；不包括 HTTP/TLS/IP 头、VPN 封装、TCP 重传。手动与家庭流量分别记账。发送前通过 `BEGIN IMMEDIATE` 计算 `可用 = 上限 − 最近24小时已结算 − 活跃预留`，预留覆盖将要发出的请求和有界响应，超额停止；流式响应应限制单次 Range 或读窗口。读写过程中在预留量内计数，事务结算并返还未消耗量。进程崩溃留下的不确定预留按上限结算一次，避免重启白得额度；时间回拨使用持久最后观测时钟防止额度提前过期。
5. 四级就绪队列依次处理显式取回、手动上传、自动小任务、家庭批量任务。同优先级在单元间轮转，一次一个有界请求或块；已开始的请求可取消。手动放行只绑定已选版本，后续快照照常排队。管理、认证或目录刷新请求设置长度限制，显式目录操作可以更新元数据但不能隐式拉取正文。

## 5. 释放、归档和还原

驻留策略有 `on_demand`、`pinned`、`nas_only`；实际驻留有 `absent`、`placeholder`、`materialized`、`partial`。dirty/上传状态与两者分别记录。对文件夹执行操作时在父记录保存意愿，展开范围后按文件记录完成状态，失败时可恢复并列出保留项。父级新操作明确展示受影响的已固定子项。

| 写前日志阶段 | 必须检查 | 失败或重启 |
| --- | --- | --- |
| `intent` | 绑定确定的快照、路径范围和处理前文件身份，列出规则外、缺 Git/ACL/xattr/ADS 等元数据及已固定成员 | 仅已证明可恢复的项可进入下一步；意外数据保留 |
| `held` | NAS 已回复对应版本、范围及有效归档引用；再核本机摘要与版本、dirty 代次、文件身份、在用状态 | 连接失败、待传或源变化时停止本机移除；暂留引用供重试 |
| `acting` | 受管位置通过原生回收请求操作，并由系统维护占位。普通目录的归档只作用于预览中选中的具体文件；逐条验证实际对象和路径归属 | 核对实际磁盘与日志，区分原始文件、已回收占位、新写入的同名文件，遇到差异保留两者 |
| `done` | 确认已经驻留 NAS／对应应保留文件仍在，提交本机 presence、数据库操作结果与监听抑制记录 | 只抑制匹配该操作、路径、原身份和代次的事件；新编辑或同名再创建作为新修改调度 |

普通目录需防止“检查完就被替换”。固定根句柄，按路径组件拒绝意外链接、挂载和 Windows reparse point，按文件身份校验。使用同卷、可恢复的私有暂存移动逐个隔离目标；移动后再次比对身份、完整摘要与元数据，发现新内容则保留并恢复到无冲突位置。处理活跃工作区、开放的写句柄和不能证明已停止写入的普通文件时，先完成 NAS 归档，保留本机内容并提示关闭写入者后重试。平台排他保障或可协调的静止条件须通过真机测试，再执行最终回收；私有暂存未真正清理前不能显示“已释放 N 字节”。绝不对子目录执行不加枚举的递归删除。归档项可通过客户端目录按原路径取回。其 NAS 引用至少保留到用户已明确解除该设备归档需求，并完成本机取回或替代留存检查。

恢复目标优先选新目录。先预检磁盘容量、大小写和 Unicode 碰撞、Windows 不可表示的名称、符号链接及元数据覆盖；在目标卷暂存到新文件，逐块与整文件校验，文件落盘后再安全替换。同名新改动保留为冲突，并让用户选用单独输出目录。工作区覆盖采用逐项日志，断电后继续或回退；桌面 UI 在整份校验通过后显示版本已恢复。有外部进程直接读取普通目录时，逐文件落盘过程可能可见；需要完整隔离时在新目录完全就绪后再交付。

## 6. 原生适配与本机 IPC v1

Mac 原生 Swift broker 在每用户登录域处理 App Group 授权的 XPC/Mach 请求，再将受限动作转发给同组的 Go Unix socket。Unix socket 所在目录仅本用户可写，两端核验本机对端；Mac broker 核验原生调用组件的签名和目标组。Windows 每用户命名管道限制登录 SID，拒绝远程连接；注册 CfConnectSyncRoot 的进程应在 WPF 窗口退出后仍可处理回调。配对令牌保留在后台凭据库，不透传给扩展。M0 验证受沙盒约束时 broker 和后台的冷启动、可取消操作和句柄交接。[Apple File Provider](https://developer.apple.com/documentation/fileprovider/nsfileproviderreplicatedextension) · [App Groups](https://developer.apple.com/documentation/xcode/configuring-app-groups) · [Windows CFAPI](https://learn.microsoft.com/en-us/windows/win32/api/cfapi/nf-cfapi-cfconnectsyncroot)

broker/桌面 CLI 与 agent 的流协议使用 4 字节无符号大端长度 + UTF-8 JSON，单帧上限 1 MiB。版本字段 `v=1`，请求含 `id,op,args`，回复含同一 `id` 与 `result` 或 `error{code,retryable}`。不识别的版本、操作、非法长度、越界 range 均返回确定错误或关闭无效流。更改状态的调用带持久操作 ID，回包丢失时对账。系统枚举、正文取回与用户命令采用独立能力；即使传入 `manual:true`，只读／系统回调也不能取得用户放行。示例为去掉长度前缀后的单帧。

```json
{"v":1,"id":"open-8","op":"fetch","args":{"unitId":"01J8Q2SJNN8XB42T0QS6JJ6ZHG","snapshotId":"01J8Q2SJNN8XB42T0QS6JJ6ZHH","path":"runs/model.bin","offset":0,"length":65536,"origin":"provider"}}
```

在外出 manual 模式中，未驻留且无一次性许可时预期结果如下。

```json
{"v":1,"id":"open-8","error":{"code":"POLICY_WAIT","retryable":true}}
```

| 原生事件 | 本机操作与数据交付 |
| --- | --- |
| 枚举／变化通知 | `list`/`changes` 接受 unit、目录、快照或游标，分页只返回元数据。根相对路径为空串，其他路径用斜线。ID 由单元及路径映射，版本另存；路径改名时兼容删除/新增事件，并保存旧路径上待传修改。File Provider 按完成枚举的锚点确认；Windows 创建占位时携带可解析的文件身份 |
| 打开文件、系统预取 | `fetch` 总是绑定版本、路径及字节范围。获准后返回 `ticket`；`poll` 可取进度及短期交付凭条。Mac 由 broker 在 File Provider 可访问的临时卷交付校验文件；Windows 从受限本机暂存句柄按回调范围交给 `CfExecute`。支持部分取回的范围以服务器验证块校验，完整恢复再校验全文件。临时路径只在受限目录下解析，文件正文不放 JSON |
| 编辑、改名、删除 | `dirty` 记录用户事件及旧版本；向原生层确认“已同步”前必须收到 NAS 对指定内容的回执。真正的删除形成项目范围内新的快照和可恢复历史；本机回收使用独立操作和意图记录 |
| 取消、休眠、进程重启 | `cancel(ticket)` 取消该等待者；最后一个消费者离开时停止对应网络读取。幂等释放句柄并完成系统回调，恢复时查询 ticket，未知的旧会话重新绑定原版本。不可用、待放行和取消映射到系统相应错误，不用零字节伪文件表示成功 |
| 固定、回收与主动取回 | 用户外壳发出 `pin`/`release`/`archive` 或指定版本的 `syncNow`；显示费用与覆盖范围。File Provider 走系统回收接口，Windows 走 CFAPI 协同的回收/固定状态；对平台可能自行回收的内容，须在告知系统该确切版本已同步且可回收前确保 NAS 存在有效保留依据；仍有未传编辑时由平台保留完整文件。任一策略拒绝原因在 GUI 和 CLI 保持一致 |

## 桌面 0.3.0 已实现的来源设置

`schedule get <unitId>` 返回 `policy` 和 `intervalMinutes`。`schedule set <unitId> --policy network|home|manual --interval N` 独立设置每个文件或项目的采集周期，范围为 1 至 1440 分钟。普通来源初始周期为 1 分钟。代理先在 SQLite 原子登记扫描时间，然后采集。排队后每次恢复自动上传都重新检查当前策略。家庭限定来源同时要求家庭地址和实际物理接口；手动来源通过用户显式发起的快照与上传进入历史。

可选的 Codex 预设使用独立来源类型 `codex`。`preset codex enable --scope <unitId> --policy network --interval 30` 创建本机历史绑定。已配对的设备和父资料库共同确定历史的目标。UI 从可写主资料库选择，首次绑定后固定目标。未启用时代理跳过采集与上传。显式 `preset codex run` 可为已配置的来源采集并按父子顺序发送队列。状态接口分别返回启用状态、策略、间隔、来源路径、父资料库、历史单元、最近 NAS 回执时间与错误。

采集器只进入两棵历史目录并读取允许的 JSONL 名称。对活跃文件固定本次长度，选择最后一个完整换行，按块生成快照。归档时移动目录也保留原快照。相同内容复用本地缓存，服务器存储继续按内容去重。

手动合并在版本历史中执行。客户端提交预览时看到的主线、分叉和逐项决定，以固定请求 ID 保证重试幂等。CAS 失败时返回 HTTP 409，需要重新预览。成功的记录包含两个父版本，客户端可以恢复或检出到新目录。协议见同目录 OpenAPI 的 merge 路径。
