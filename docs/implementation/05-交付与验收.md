# 从第一项提交到可安装版本

| --- | --- | --- | --- |
| T01 工程基线 | 无 | Go module、三个入口、三目标构建、本机 TLS 测试工具、SQLite 初始迁移 | 可重建的工具链清单；新目录启动，重启后读取同一库，产物按 OS/架构命名 |

## 2. 可复现的验收数据

开发时把生成器和预期清单放入 `testdata/`。每次报告记录生成器版本和结果摘要。文件名和内容确定性生成，测试不依赖私人项目。

- **基础目录 F1。** 空目录、0 字节文件、只有一个 ASCII 字节的文件、同样内容的第二份文件、一个可执行脚本、一条指向根外的符号链接。验证去重与恢复，链接按链接记录，禁止把目标内容读入同步根。
- **代码项目 F2。** 生成 100 个目录，每目录 500 个文件，序号 00000–49999。用由序号确定的内容保证每个文件唯一。第二版只改前 120 个，使其总新长度为 819,200 字节（前 80 个各 6,827 字节，后 40 个各 6,826 字节）。加入已托管且未变的 6 GiB 文件，记录增量扫描、缺块协商及 API 请求数。
- **传输与预算 F3。** 文件大小恰为 4 MiB、4 MiB + 1、10 MiB 和 10 MiB + 1；另有 20,000 个互不相同的 1 KiB 文件。4 MiB 边界验证最后一块，10 MiB 边界分别检查单项大小门槛与包含清单开销的总预算。并发预算用两个预计各传 2 MiB 的任务和 3 MiB 剩余额度。
- **边编辑边同步 F4。** 两个独立客户端缓存同一父版本。上传到一半修改源文件、切换 Git 分支，或在快照冻结后再编辑。另造一个有暂存区独有改动、未跟踪文件和子模块的 Git 目录。检查本机已采集版本、待处理变更、NAS 主线及冲突版本。
- **媒体和现有 NAS 目录 F5。** 放入可解码图片、PDF、带中文名的文本、随机二进制和 12 MiB 可变文件，显式登记只读 external 单元；另建一个未授权单元。用于手机浏览、分页、权限和续读验证。

## 3. 桌面和服务端联合验收

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| A01 原子发布 | 发送 F1 新版的部分对象，另一台设备同时更新目录；之后补齐并发布 | 读端只见旧版或完整新版；发布前后分别保存快照 ID 与树摘要。会话重试不产生额外版本 |
| A02 并发和离线 | 双端由共同父快照修改同一文件，先后上线。另一端离线连续保存两个检查点 | 主线可继续读取；分叉呈现共同祖先；两个离线检查点能按父子顺序找回。恢复旧版到新目录不改变 NAS 头 |
| A03 网络身份 | 家庭 Wi-Fi、有线、异地 Tailscale direct、中继、热点、证书错误、断网分别执行相同任务 | 仅家庭已验证端点允许自动大文件。在家开始的大传输切到热点后停止自动续发；抓取应用侧记录核对实际物理路线 |
| A04 外出增量 | 上传 F2 的第二版，再更改 6 GiB 成员一个字节，继而把该成员另行登记为独立单元 | 首次小改动对未变大文件传输正文为 0；含已改大成员的项目整体等待；显式拆出后代码可单独发布 |
| A05 预算和手动 | F3 小文件批次、并发预算、重试扣账；手动放行已冻结版本并产生下一版 | 单项、整批和滚动预算分别生效；并发只启动可获预算的任务。手动例外只对该版本生效 |
| A06 驻留与破坏性事件区分 | 一台设备释放文件后重启，再回家；另一台固定离线。随后显式在一个新版中删除该路径 | 释放不产生远端删除，不自动回填；显式删除才更新当前树。释放时的受保护版本和另一设备的本机状态可核实 |
| A07 留存和崩溃 | 在对象持久化前、持久化后但提交前、提交后回包前、本机回收过程中分别强制终止测试进程 | 重启后可对账；无引用的临时对象可收回。已有保留引用的内容能从备份和在线库恢复；缺少回执时不回收源文件 |
| A08 系统回调与工作区 | 预览大占位文件、取消打开、后台退出重启；下载时本机用户编辑；跨平台还原不合法文件名 | 能解释并取消请求；同一套预算生效。用户修改保留，无法表示的路径进入恢复报告；不会把半成品标成最新 |
| A09 类型与范围 | RAW + XMP、Mac 文稿包、未完成采集、活跃数据库导出、匹配忽略规则的已跟踪内容 | 组内成员同时可见。需应用导出的任务一直等待一致来源；变更范围有预览和版本记录；本地范围外内容不会被项目释放误删 |
| A10 安装和回滚 | 在 fnOS 测试子目录安排两个已发布版本、一条分叉、一个 hold；备份，升级，恢复到隔离目录 | 按 SHA-256 核实版本；授权和 hold 可恢复；旧二进制遇到不兼容 schema 明确拒绝写入；记录实际恢复时长及占用 |

## 4. 性能和发行记录

同一台设备上分别记录初扫、已索引后的空扫、120 个小文件变更、远端分页、重试一个未确认块。记录 OS、CPU、介质、网络类型、工具链、文件数、墙钟耗时、CPU 时间、RSS 峰值、SQLite 与对象体积、上／下行有效字节、请求数。冷启动和热缓存各跑三轮并保留原始数据。首版的确定条件是“一个项目任务、一份可见版本、未变大文件正文 0 字节、在途以外自动传输不越额度”。秒数和 MB/s 在目标机器上建立基线后再设发布阈值。

每版同时列出 Go 核心、服务端 schema、HTTP 协议、原生适配和移动包版本。发布记录区分“本机模拟已过”“真实设备已过”“尚无对应设备验证”。在真实 Mac、Windows、Android、鸿蒙和 NAS 上逐项有结果之后，才能称整套跨端发布通过。
