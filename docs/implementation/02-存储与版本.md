# NAS 存储、版本提交与恢复

本规范定义 Go 服务端与所有快照生产者共同遵守的 v1 对象格式。桌面和手机消费者通过[读取协议](openapi.yaml)取得目录或文件；服务端以 SQLite 作为版本和引用的权威索引，以不可变文件保存对象。项目、文件组和单文件共用提交逻辑。单文件单元使用含该文件的目录根。

## 1. 进程、目录和设备授权

目标为飞牛 fnOS 的 Linux/amd64。建议在已挂载的 ZFS 数据卷上单独建目录，例如 `/vol2/kiriusdrive`；部署时选择的服务账户拥有这个目录。由管理员在命令行指定绝对路径，以 `kdrive-server serve --config <file>` 启动。容器部署绑定同一目录。数据卷首次初始化生成随机 `store-id` 并记录预期挂载源。启动和从 I/O 故障恢复时验证卷标记、挂载源以及独占实例锁，错误时进入不可写状态。禁止自动在空挂载点初始化同名数据仓库。

| 路径（相对于数据目录） | 内容 |
| --- | --- |
| `store-id`、`state/meta.db` | 卷身份、SQLite 主库；使用本地文件系统、WAL、`synchronous=FULL`、每个连接开启 `foreign_keys`，写事务有界等待 |
| `objects/{kind}/{digest前两位}/{digest}` | `chunk`、`file`、`tree` 三类不可变文件，摘要使用 64 位小写十六进制；相同种类和摘要跨版本去重 |
| `incoming/{sessionId}/`、`gc-trash/{sweepId}/` | 同卷临时写入与操作中断后可辨认的回收区。临时文件名由服务生成 |

监听 TLS，只允许登记的家庭端点和私网入口。客户端验证已登记的 NAS 身份及证书主机名；直连 IP 时仍保留经验证的证书名或初始可信配对绑定。Docker 不是必需条件。SSH 密码仅属于运维。NAS 本地管理员创建带到期时间、角色和单元范围的一次性配对码；交换时验证有效期、限制尝试、原子消费并分配设备。客户端预先生成设备 ULID 和 32 字节密码学随机令牌并写入系统密钥库；配对通过已验证 TLS 发送，数据库只存令牌校验值，服务端按设备撤销。设备的实际权限为角色和单元授权的交集；每个入口、Range 子请求、缓存复用、跨单元挂载都重新检查。设备凭据、私钥、配对码和文件内容不进入日志。管理操作限本机授权的 CLI。

## 2. 可互操作的二进制对象格式

所有整数为固定宽度大端。下文 `u8/u16/u32/u64` 是无符号整数，`i64` 为二补码有符号数，`H` 总是原始 32 字节。四字符标记为精确 ASCII 字节。对象 ID = SHA-256(完整正文)，不加入 kind 前缀；查找键为 `(kind, digest)`。网络摘要为小写 hex。拒绝有多余尾字节、越界、未知标志、重复条目或非规范分页的输入。树展开使用有界深度、条目数和总引用数；达到实例上限要返回明确的限制错误，保留上一版本。组装前检查乘加溢出。

**数据块。** `chunk` 的正文是原始文件字节。固定 4 MiB = 4,194,304 字节，从偏移零切分。最后一块可短于 4 MiB，整除时没有额外空块。空文件引用零块。每一 `chunk/file/tree` 对象的最大正文为 4 MiB。小文件请求可合批，每批至多 256 个对象、合计至多 4 MiB 原始正文；网络打包不参与摘要计算，索引仍逐对象确认。

**文件清单。** 根为 `kind=file`，格式 `"KDF1" | length:u64 | wholeFileSHA256:H | chunkCount:u32 | payload`。`chunkCount = ceil(length / 4194304)`。块数 0–256 时 payload 是按文件偏移顺序排列的块摘要数组；块数 >256 时 payload 为 `pageHeight:u8 | rootPageDigest:H`。文件清单的分页对象同属 file：

- 叶为 `"KDCL" | n:u32 | n × chunkDigest:H`；内节点为 `"KDCI" | height:u8 | n:u32 | n × childPageDigest:H`，叶级高度为 0。
- 从第一块开始每 256 个引用划一页。每级从左到右每 256 页组成下一级，直到只剩一页。仅最右页可不足 256，每个分页对象的 n 为 1–256。内节点的所有子页高度一致，且比它低 1。验证还须核对全树规则，例如 257 个块形成两个叶页和一层内页。服务端首次接受一个新文件清单前，按顺序校验块数、各块长度及整文件 SHA-256。已验证的不可变文件清单可复用验证结果。

**目录树。** 名称是原始 UTF-8 字节，长度 1–255，不做 Unicode 归一化或大小写折叠。同层名称按无符号字节序严格递增。禁止空名称、NUL、`/`、`.` 和 `..`；POSIX 名称内的反斜线保留为字面字符。不能无损表示的名称由客户端列为覆盖缺口。目录叶对象为 `"KDTL" | n:u32 | entries...`。每项公共字段为 `nameLen:u16 | nameBytes | type:u8 | mtimeNs:i64`。mtime 单位是 UTC Unix 纳秒，未知用最小 i64。类型特有字段如下：

| type | 特有字段 | 如何读取 |
| --- | --- | --- |
| 1 文件 | `exec:u8 | fileDigest:H` | exec 为 0 或 1，表示是否有执行位；查找 file 根清单 |
| 2 子目录 | `treeDigest:H` | 指向下一级文件系统目录的独立树根，可指向空树 |
| 3 符号链接 | `targetLen:u16 | targetBytes` | 目标保存原始字节（1–4095、无 NUL）。归档及服务端浏览只读链接本身；跨平台无法安全还原时报告该路径 |

按已排序条目每 256 项构建一叶；空目录为单个 n=0 叶。超过 256 项的目录按上述 256 扇出规则逐层生成内节点 `"KDTI" | height:u8 | n:u32 | n × childPageDigest:H`，同为 tree。只有目录根自身为空时可有空叶。验证内节点时保证跨页名称单调和高度、分页边界一致；可在索引中缓存页最小/最大名，加速分页。目录边和同目录分页边分别解释，子目录不能冒充同目录页。工作树根自身的显示名及时间存在单元元数据里。v1 恢复范围为正文、名称、空目录、符号链接、上述时间和可执行标志。ACL、硬链接关系、Windows ADS、macOS 资源分支与其他扩展属性需要单独列为覆盖缺口；仅归档普通字节不能授权清除含未保护数据的原文件。

**内置校验向量。** 项目含普通文件 `a.txt`，正文为三个 ASCII 字节 `abc`（无换行），exec=0、mtimeNs=0。下表摘要均为正文 SHA-256。验证客户端在内存运行下面的 Python 标准库片段即可复算；Go 端用自己的序列化器产生同样的字节。

| 输入 | 字节数 | 摘要 |
| --- | ---: | --- |
| 原始空正文 | 0 | `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855` |
| 空文件根 | 48 | `15d856b25212a2fb5adad44e2979514fa3f96f2bc022ecab3be8ba21bc334938` |
| 空目录根 | 8 | `7326cd7e8bcace983896e6eb726579fb3bb3c038cc1e20968b0cafb8178422f1` |
| 原始 abc | 3 | `ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad` |
| abc 文件根 | 80 | `93767d9a46cd34f2b0f34b2bcb221cec09e560014712d3f84d343e2eb03529db` |
| 含 a.txt 的目录根 | 57 | `4c20096fc8f960f04aa7211e6a2d28b83d68c2490b96ea8e632dc4975a416204` |

```python
from hashlib import sha256
from struct import pack

def digest(data):
    return sha256(data).digest()

empty_file = b"KDF1" + pack(">Q", 0) + digest(b"") + pack(">I", 0)
empty_tree = b"KDTL" + pack(">I", 0)
chunk = b"abc"
file_root = b"KDF1" + pack(">Q", 3) + digest(chunk) + pack(">I", 1) + digest(chunk)
entry = pack(">H", 5) + b"a.txt" + pack(">BqB", 1, 0, 0) + digest(file_root)
tree = b"KDTL" + pack(">I", 1) + entry
for raw in (b"", empty_file, empty_tree, chunk, file_root, tree):
    print(len(raw), digest(raw).hex())
```

## 3. SQLite v1 迁移清单

ID 对外为规范大写 ULID；摘要通过 32 字节 BLOB 存入 SQLite。所有 `*_ns` 为 UTC Unix 纳秒 INTEGER；逻辑时序按游标或父子关系。以下为实现迁移必须表达的关系，PK 表示主键，UQ 表示唯一约束，关联键使用外键。单元内资源统一用 `(unit_id,id)` 做可被引用的复合唯一键，防止跨单元拼接。

| 表 | 主要列、约束与索引 |
| --- | --- |
| `schema_migrations`、`store_meta` | PK(version)、迁移时间及校验值；PK(key)、value，记录 store-id、格式及变更游标最小保留值 |
| `devices`、`unit_grants`、`pairing_codes` | devices PK(id)、UQ(token_hash)、role、revoked_at；grants PK(unit_id,device_id)、可读写范围；配对码 PK(code_digest)、expiry、scope、role、consumed_at、attempts。只读角色的授权不含写能力 |
| `units`、`scope_revisions` | units PK(id)、kind、name、head_id 可空、external_root_id 可空、deleted_at；scope PK(unit_id,device_id,revision)、首次见到的时间。scopeRevision 是设备在该单元内给本机规则分配的正整数（API ≤ 2^53−1），客户端保存完整规则和递增计数器。服务端在提交时记录已见修订号；允许新修订及离线迟到的旧修订。scopeRevision 不能改变设备权限。规则作用后的范围由冻结的树及 links 体现。本地 admin 保存 external 路径映射 |
| `objects`、`object_edges` | objects PK(kind,digest)、length、status、verified_at、storage_path，CHECK(length BETWEEN 0 AND 4194304)。edges PK(src_kind,src_digest,ordinal)、dst_kind、dst_digest、edge_role。验证成功后建边，反向索引用于审计。GC 删除时先清理待扫集合内边或在事务末检查外键 |
| `snapshots`、`snapshot_links`、`attachments` | snapshots PK(unit_id,id)、parent_id 可空（与 unit_id 复合外键指向同单元父）、root_digest、scope_rev、device_id、created_ns、label、checkpoint、git_head、git_branch、resolved_fork_id、receipt、disposition、availability。索引 (unit_id,created_ns,id)、(unit_id,parent_id)；checkpoint=true 即受保护，普通说明文字不决定是否保留。links PK(unit_id,snapshot_id,mount_path)、target_unit、target_snapshot；attachments PK(unit_id,snapshot_id,name)、kind、file_digest |
| `upload_sessions`、`session_objects` | PK(id)、UQ(device_id,request_id)、client_snapshot_id、unit_id、base/head、scope_rev、frozen_envelope、params_hash、state、expiry、receipt；session_objects PK(session_id,kind,digest)、length、state、verified_at。索引到期的活动会话 |
| `request_results`、`changes` | 已提交幂等操作 PK(device_id,operation,request_id)、canonical_params_hash、result 与持久回执引用；changes PK(seq INTEGER 单调增长)、unit_id、snapshot_id、event、committed_ns。索引 (unit_id,seq) |
| `holds`、`leases`、`gc_runs` | holds PK(unit_id,id)、snapshot_id、path、device_id、created_ns、released_ns；幂等键为客户端预先落盘的 holdId，原设备或本机管理员有权解除；leases PK(id)、kind、root/session、expiry；gc_runs 保存 sweep_id、阶段、候选集合/移动日志。持有时间、撤销设备都不能自动解除归档引用 |

客户端为每个待发布版本生成独立 snapshotId，即使根摘要相同也可保留两个不同说明的检查点。幂等参数使用解码后的类型化字段、固定顺序和长度前缀进行比较（也可保存规范化字段后逐项相等比较）；忽略无意义的 JSON 键顺序，对字段缺省和显式可空值按 OpenAPI 定义一致处理。每次请求验证设备的当前权限。

## 4. 上传、分叉与原子发布

1. **冻结提交。** 会话创建绑定请求方、单元、客户端 snapshotId、parentSnapshotId、expectedHead、rootDigest、scopeRevision、命名信息、links 和 attachments；同时冻结 checkpoint、gitHead、gitBranch 及 resolvedForkSnapshotId。finalize 无正文，会话 ID 标识幂等发布。普通提交的 expectedHead 等于 parentSnapshotId；新单元均为空。离线多版本按父先子后提交，会话可先冻结离线父 ID，finalize 时父版本仍未知则返回可补传的依赖错误。服务端登记本机规则修订号并检查授权；旧修订的内容保留原边界，界面可提示规则变化。客户端调整规则范围时，不得把因此消失的工作路径解释为物理远端删除。
2. **协商去重。** 只向设备公布本单元已授权且被保留版本引用的对象和本会话已持久接收的对象。作为其他用户/单元的唯一对象仍要求此次提供正文，服务器可以在后台物理去重。新根可引用本单元上一版已验证子树，省去重复上传和整树网络往返。仅凭摘要不授予读取或挂入快照的能力。单对象写入、去重和文件存在判断必须在同一对象键的锁或等效序列化机制内完成。
3. **落盘与确认。** 流式验证种类、长度、SHA-256 → 写到 incoming 临时文件并 fsync → 同卷无覆盖安装目标文件 → fsync 新建的各级目录及目标目录 → SQLite 事务登记对象与会话持有关系 → 返回确认。相同键已存在时复核大小和可信校验状态。任何新建目录的落盘都须持久化其父目录项。先有对象后有元数据，崩溃产生的无引用文件可待清理；同名对象缺损时捕获错误并隔离，不能凭目录项存在返回成功。包内逐项确认，重连查询会话中的已确认项。会话建议在连续七天无成功活动后过期；重新协商仍受授权的可复用项。
4. **验证可恢复性。** 在对象生命周期保护下遍历新根、附件和 pinned links。校验清单格式、引用的 kind、大小、摘要、循环、路径和可达权限；复用已验证的不可变子树/文件结果。区分“NAS 已写入一个块”和“NAS 已确认一个完整版本”。发布事务之前完成耗时读盘和哈希，事务中复核租约和本次检查依赖的状态。对象键若与 GC 竞争，由租约/同一存储写锁保证其物理内容存在。
5. **条件发布。** `BEGIN IMMEDIATE` → 重验设备授权和同 ID 旧回执、对象租约、同单元父节点、相关源快照/链接 → 插入快照及包含的引用。如果 head 与 expectedHead 同值（包括双方 NULL）且父存在或为首次提交，执行带相同条件的 head 更新，记 published；否则保存完整 fork，不改变当前 head。根快照并发也可产生 fork。两台设备都能查看并恢复有权限的分叉。分叉的离线后代继续给出原父 ID，保持 fork。解决分叉时以当前主线为 parent，resolvedForkSnapshotId 标记同单元已有的分叉；只有成功推进主线才关闭相应冲突，基线再次过时仍保存 fork。写 changes 与 receipt，提交后才通知客户端。恢复某旧版到单元头是显式新提交，以此时主线为父，内容来自已验证的选定版本。
6. **重试。** 请求 ID 或本单元内的 snapshotId 已使用且字段相同就返回原回执；ID 相同而参数不同应明确报冲突。同一确认包丢失或并发 finalize 不能生成两个历史条目。权限失效时先拒绝再查询回执。读端仅枚举已提交的快照。增量读取按 seq 与权限过滤分页；游标太旧时重新取得单元和头版本后继续。

**Git 和混合项目。** 工作树中的 `.git` 由客户端单独处理。Git bundle 作为 `{kind:"git-bundle",name,fileDigest}` 附件引用完整 file 根。归档设备记录 refs 和覆盖范围、验证可重建后方可声明“含 Git 历史”；首版优先全量自足 bundle。引入增量 bundle 时必须为其前置对象增加可验证、可回收追踪的引用。附件名限 1–255 字节、单段 ASCII，匹配 [A-Za-z0-9_-][A-Za-z0-9._-]*。具备 sync 权限的客户端使用快照范围内的 attachments/{name} 下载整包（支持 Range），或由 readSnapshotObject 在验证所属单元、快照和附件闭包后读取清单及数据块。reader 设备通过目录/正文接口读取工作文件，禁止从附件元数据和通用对象读接口绕开授权。

被拆出而独立调度的数据集仅登记边界，不阻塞代码提交。配套恢复时父快照用 `links:[{mountPath,unitId,snapshotId}]` 固定子单元的已发布版本，要求挂载路径从父树中排除且无路径重叠。验证时提交者对目标单元有读权限；链接只可以指向在父快照创建前已持久存在且可恢复的版本。慢数据集先完成，最后一次父提交才使这套配套清单可见。子单元独立头可能更早可见。读取链接内容须同时持有源、目标单元权限；不返回未授权子单元的清单、对象或下载地址。历史或 hold 保留父版本时，同时保护它声明的配套目标。

## 5. 归档引用、删除和垃圾回收

归档操作使用明确的单元、快照、相对路径和设备。服务端在受锁定的已发布快照上完成可达对象校验，读取并对比与请求范围相关的实际存储摘要；最近一次上传回执本身不能替代发现磁盘损坏的检查。批量校验可合并相同内容。校验通过后在事务中将临时读取租约转为持久 hold，返回 hold ID 和精确版本。本机在此之后还须检查是否有新写入。首版允许以整快照为最小物理保留范围，即使 hold 指向单一路径。将整个版本保留下来会多占空间，界面应如实说明。

释放 hold 是独立幂等变更。设备撤销、断线、缓存清理或删除同步关系都不会顺带解除 hold。远端逻辑删除形成新版本或单元 tombstone，先前内容仍受所有持久引用约束；恢复到旧版创建新历史记录。业务历史保留首版由管理员预览后手动触发，初始不自动过期。被裁剪版本保留最小身份和父链信息，状态显示“内容已清理”，禁止对其发新 hold。当前主线、待解决的分叉及其必要基线、命名检查点和有效 hold 都是保护根。

**首版回收算法。** 管理员确认的 sweep 在单实例仓库维护写锁下运行；阻止发布、新上传对象、发新读取租约和创建 hold，已有读取/上传的租约或会话及其已确认对象全部计入标记。实现必须让正在打开对象的读者先获得租约，过期时间覆盖读操作且可续期；维护锁未取得前任何标记结果只作预估。事务登记 sweep ID，标记所有保护根及跨单元 links、附件、持久对象页，明确区分历史父边与恢复内容边。仅在保留政策选中了父版本时沿该父版本标记内容。写入待回收列表，在同卷将对象移动到隔离区并 fsync 目录后更新状态；恢复时按日志和实时引用复核，恢复仍被引用的对象，确认无引用的隔离项才可清除。GC 异常退出时暂停常规写入，完成恢复或回滚维护日志再开放服务。后续可实现并发 sweep，需证明屏障和双重校验语义等价。

## 6. 手机只读目录与外部文件

受管快照通过单元、版本以及文件路径解析到 file 清单，Range 按偏移映射块，ETag 对应该版本的实际正文。读取租约保护整个响应；多次续读绑定同一版本，已裁剪则通知调用方刷新。每次修改权限立即作用于新的读取请求。reader 凭据不能创建会话、发布快照、修改 hold 或写入外部目录。

external 单元由本机管理员显式选择现有目录，仅提供当前内容。用受信根目录的文件描述符进行相对遍历，禁止目录/最终目标跟随符号链接与穿越根，解码 URL 一次后逐段校验，枚举与取数都应用同样的规则。访问移动或替换后的目标必须重新校验，拒绝把服务密钥或自身数据目录纳入外部共享。外部文件通过 HTTP 强 ETag 与 If-Match 绑定同一次读取的版本事实；inode、mtime、size 适合检测变更，但不能单凭它们承诺强内容一致性。快速路径可用只读文件系统快照；通用路径在可验证的冻结或稳定读取条件下复制到私有暂存、校验并按完整内容摘要服务，给该只读副本有限时长缓存，Range 仅针对同一个副本。源版本不符、缓存过期后又无法重建同一摘要或写入持续发生时，按 OpenAPI 的前置条件错误处理，要求刷新文件详情，不能接着拼另一版本。外部读取临时副本不自动进入历史或归档。

## 7. 备份、恢复、升级与故障注入

- 离线备份基线：暂停接入写请求，等待存储操作结束，正常关闭 NAS 进程，在同一时点复制完整数据目录（含 SQLite 的 WAL 状态、objects、store-id 和未完成日志），另行保护配置、证书和令牌校验所需密钥。可在同一数据集完成受控 ZFS 快照后重新开放服务，再从快照导出。元数据与对象位于不同卷时，必须在整个取样期间保持统一写屏障。不能仅复制正在使用的 meta.db 主文件。
- 恢复到独立测试路径后校验卷身份、数据库完整性与外键，复核所有保留根到对象的引用闭包、内容摘要和归档引用。对曾在另一设备上恢复过的旧备份，先在隔离环境扫描设备授权和撤销状态，以免过期备份复活已撤销令牌；上线前更新设备认证状态并使桌面端全量核对基线。
- 升级锁定 schema 版本，先做成套可回退备份，迁移有校验值且可中断恢复，旧程序遇到新 schema 必须拒绝写入。回退恢复匹配的程序、元数据和对象视图；生产已接收新版本时先导出并核对新增数据，再决定迁回方式。
- 故障测试点依次覆盖对象安装前、对象目录 fsync 后、索引登记后、finalize 前、提交后回包前、hold 持久化后、隔离对象后。每次杀死进程并重启，断言任何可见且受保护版本均能按摘要完整恢复，幂等重试后只有一次提交，未发布的版本不会成为主线。用两个从同一父版出发的客户端、迟到子版本、同一摘要不同 kind、257 项目录/257 块文件、批内重复摘要、归档与 GC 竞争、外部文件替换和跨单元拒绝授权分别验证边界。
