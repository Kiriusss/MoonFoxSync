# 心狐同步 Windows 客户端

解压 Windows 桌面包，双击 `心狐同步.exe`。图形入口使用 C#，主导航、同步概览和项目列表使用 WPF/XAML，操作对话框与任务栏托盘使用 WinForms，目标环境为已安装 .NET Framework 4.8 的 Windows 10/11。将 `心狐同步.exe.config`、`kdrive.exe`、`kdrive-agent.exe` 保留在程序目录。GUI 直接启动同目录的 Go CLI，并与 CLI 共用凭据管理器、SQLite 队列和应用缓存。

## 使用

1. 从「概览」点击「配对服务器」，填入 HTTPS 地址和一次性配对码，使用私有 CA 时选择公开证书。概览显示实际连接状态、资料库数量、待上传快照和最近活动的项目以及每个项目的 NAS、Git 状态。
2. 在「资料库」选择有同步权限的资料库，可绑定项目目录或单个文件，设置版本名并保存快照。「同步队列」显示本机所有资料库的快照，离线时也能查看。点击「立即同步」，即可按顺序上传点击时已经排队的快照。只传一个版本时，选中快照并点击「上传选中快照」。
3. 在「资料库」选择历史版本，双击目录逐级浏览，双击文件取回并阅读。外部只读库提供 NAS 当前内容，下载目标为新文件。在「下载缓存」可对选中版本取回、打开或释放本机缓存。
4. 在「设置」启用「登录 Windows 时启动」。下次登录后程序静默驻留在任务栏通知区域。程序移动位置后请从新的固定目录再次启用。Windows 在任务管理器禁用该启动项时，设置页会提示。
5. 左键点任务栏通知区域的狐狸图标打开快捷面板，右键打开菜单。关闭主窗口会收起至任务栏，已启用的自动检查继续运行。重复启动程序可唤回已有窗口。要结束后台运行，在托盘中选择「退出心狐同步」。
6. 在「同步策略」开启自动同步后，接电时每分钟检查，使用电池时默认仅手动，也可选择每 1 小时或 4 小时检查一次。拔电会停止正在运行的自动检查，已开始的手动操作可继续。接电后恢复原有调度。可登记家庭 NAS 私有 HTTPS IPv4 和物理网卡名称。使用外出小任务模式时，每个任务最多 10 MiB，24 小时预算为 100 MiB。保存策略后生效。托盘的「立即检查」按当前策略扫描来源。点击托盘「待上传」旁的「立即同步」可直接上传队列中的快照，自动检查暂停或外出时也可使用。操作期间仍可打开队列查看文件进度和速度。完成后显示各项结果，失败原因可从队列中的「查看失败详情」打开。

## 共享项目

在「项目 → 导入项目父目录」选择本地项目集合，勾选要导入的子目录。对每个目录，从清单选择另一台电脑已经使用的 NAS 项目，或在指定备份空间新建独立项目。清单显示项目名称、备份空间和项目短 ID，Git 项目与普通目录均可手动关联。导入前会逐行展示本地目录和 NAS 目标。已绑定的目录如要改绑，需要勾选「确认重新关联」，旧 NAS 历史保留。若仍有待上传快照，先完成上传。

新导入的 Git 项目默认备份整个工作树。被 Git 忽略的普通文件无论大小都随项目调度。「全选」也包含将来新增的忽略文件。点击文件可以单独取消勾选，清空后则只备份明确勾选的忽略文件。项目页可随时修改；升级会保留过去保存的自定义选择。

主窗口与任务栏面板共享项目活动清单。项目页分别显示 NAS 主线和 Git 上游，与 NAS 已同步的工作树仍可能有尚未提交的 Git 改动。程序运行时定期检查项目，Go 核心对联网核对结果使用 15 分钟缓存。自动检查通过 Git 上游引用判断远端是否变化。若本机缺少远端提交，项目显示「Git 远端有变化」。手动深度检查可能取回 Git 对象，以比较双方领先或落后的提交数。「接收 NAS 主线到新目录」恢复并切换绑定，原工作树保留；新工作树只包含快照文件。「版本时间线 → 只看分叉」可选择并另存并发产生的版本。

## NAS 版本时间线

在「项目」或托管「资料库」打开「版本时间线」。任何有读取权限的设备都可浏览历史、恢复到新的本地目录和查看保存策略。同步设备还可执行以下操作。

- 「恢复为当前版本」会用选定时间点的内容创建新的 NAS 主线版本。确认前可查看来源与旧主线、指定新版本名称。
- 「删除并重建」会先从 NAS 取回预览，逐条显示受影响的时间点、原父版本和重建后的父版本。受保护的时间点会显示原因。确认后服务器按刚才核对的计划执行，结果会显示重建数量。
- 「历史保存策略」可选择保留全部、最近 1–10000 个时间点或最近 1–3650 天。保存前会显示 NAS 预计隐藏的时间点数量和额外保护的数量。当前主线、未合并分叉及已被副本持有的时间点受保护。移除记录属于逻辑删除，NAS 不会立即释放物理空间。

NAS 发现主线或依赖关系变化时会拒绝旧操作，窗口会重新读取时间线并提示再次确认。

## 合并分叉到 NAS 主线

在「项目 → 版本时间线」选中一个分叉，点击「手动合并分叉」。也可以从资料库的版本清单选中分叉进入。同步权限可执行合并。预览显示当前主线、来源分叉、共同祖先，以及自动变更和需处理的路径。选择冲突后可切换三方内容，文本按纯文本预览，最多显示 128 KiB；二进制、目录、链接和已删除路径各自标明。

逐项选择保留主线、采用分叉，或在提供另存路径时同时保留。完整的文本预览支持手动编辑并保存解决内容。填入新版本名称，最后核对目标和冲突数，再发布新快照。主线在此期间发生变化时，重新预览并复核选择。合并针对 NAS 快照，本地工作树和 Git 分支由各自的现有流程更新。

在「设置 → 同步策略 → 按来源设置」可分别为已绑定的单文件和项目设置家庭网络、跟随网络或仅手动策略，以及检查间隔。默认跟随网络策略，每分钟检查。

## Codex 对话历史

打开「设置 → Codex 对话历史」，选择用于备份的 NAS 主资料库、网络策略和 1–1440 分钟的检查间隔，点击「启用备份」。默认间隔为 30 分钟，首次指定的目标资料库会固定显示。目标资料库的授权设备可读取保存的对话和工具输出。自动备份跟随全局自动检查开关，选定资料库后可随时手动「立即备份」，包括停止自动备份后。设置页显示实际源目录、最近备份和错误，NAS 离线时可调整已有配置。

## 构建和验证

在项目根目录运行以下 PowerShell 命令。需要本仓库指定版本的 Go，以及 .NET SDK 或 Windows 自带的 .NET Framework C# 编译器。使用 SDK 的机器可以通过 NuGet 取得 net48 参考程序集。

```powershell
.\client\windows\build.ps1
```

默认产物放在 `dist\windows-amd64`。ARM64 使用 `.\client\windows\build.ps1 -Arch arm64 -OutDir dist\windows-arm64`。界面为 AnyCPU 程序，两个 Go 程序按所选架构编译。

制作 Windows x64 安装程序需要 Python 3 和 WiX Toolset 3（含 WixUIExtension 和 WixUtilExtension）。在 Windows 上将含有 `candle.exe`、`light.exe` 的目录加入 PATH，然后运行：

```powershell
.\client\windows\build.ps1 -Msi
```

默认输出为 `dist\MoonFoxSync-Windows-x64.msi`。发布前在 Windows 测试用户下双击检查安装向导，从开始菜单启动并退出客户端，再次运行 MSI 验证修复与卸载。升级验证应先安装上一发行版，再运行新 MSI。完成页默认勾选「启动心狐同步」，可取消勾选。静默安装、修复与卸载完成后不会启动客户端。

本阶段在 macOS arm64 使用 Microsoft .NET SDK 10.0.404 和 .NET Framework 4.8 参考程序集完成 Release 交叉编译。Go CLI 已通过 TLS 集成测试及 Windows 交叉编译。Windows 真机上的首次配对、系统凭据管理器、文件对话框、网卡识别和高 DPI 显示仍需实机验收。

## 移除本机资料

移除本机项目时，先在预览中核对项目、快照数和待传数。已下载的缓存和该项目独用的快照对象会被清理，工作目录原件和 NAS 历史保留。重置整个客户端还会清理其他本机绑定和设备配对信息。
